# Локальный запуск (без Docker) — рекомендуется для первой настройки

Локально браузер открывается на вашем экране, и вы видите, что он делает,
поэтому именно так удобно подобрать селекторы.

## 1. Создайте Telegram-бота
1. В Telegram откройте **@BotFather** → `/newbot` → задайте имя и username.
2. Скопируйте выданный токен (`123456:ABC...`) — это `TELEGRAM_BOT_TOKEN`.
3. Откройте **@userinfobot**, нажмите Start — он покажет ваш числовой `Id`.
   Это `TELEGRAM_ALLOWED_CHAT_ID`.
4. Откройте вашего нового бота и нажмите **Start** (иначе он не сможет вам писать).

## 2. Установите Python и зависимости
Нужен Python 3.10+.

```bash
cd order-bot-project
python -m venv .venv

# macOS / Linux
source .venv/bin/activate
# Windows (PowerShell)
.venv\Scripts\Activate.ps1

pip install -r requirements.txt
playwright install chromium
```

## 3. Заполните .env
```bash
cp .env.example .env        # Windows: copy .env.example .env
```
Впишите `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_CHAT_ID`, `SITE_LOGIN` (email)
и `SITE_PASSWORD`. Оставьте `HEADLESS=false`, чтобы видеть браузер.

## 4. Запуск
```bash
python -m app.main
```
В консоли должно появиться `Telegram bot polling started`.

## 5. Управление из Telegram
1. `/start_session` — бот откроет браузер и введёт email/пароль.
2. Когда сайт запросит 2FA, бот напишет «Введите код 2FA» — отправьте код
   обычным сообщением (только цифры).
3. После входа сессия сохранится в `./data/auth.json`, в следующий раз
   код не понадобится, пока сессия жива.
4. `/status` — состояние, `/stop` — остановить цикл.

### Что бот присылает при авторизации
- **HTML-дамп и скриншот страницы входа** уходят в Telegram при каждой новой
  авторизации — видно, какую разметку бот реально получил.
- Если страница авторизации **изменилась** (формы нет — бот ждёт Cloudflare и
  форму входа до `LOGIN_FORM_TIMEOUT_S`, по умолчанию 90 c; другой класс формы)
  или вместо кабинета сайт показал **капчу/антибот** —
  бот шлёт HTML+скриншот в Telegram и **НЕ пишет «сессия успешна»**: сначала он
  дожидается, пока страница перестанет редиректить, и только потом решает.
- Все дампы дополнительно сохраняются локально в `./data/debug_*.png|html`.

### Несколько админов (управление одним ботом в несколько человек)
- В `.env` перечислите id через запятую/пробел:
  `TELEGRAM_ALLOWED_CHAT_ID=3036948,111111111,222222222`
  (или заведите отдельную строку `TELEGRAM_ADMIN_IDS=111111111,222222222`;
  также понимаются `TELEGRAM_SUB_USERS` / `SUB_USER`).
- Любой из админов может слать команды; уведомления и файлы-дампы приходят
  **всем** админам.
- Новый человек узнаёт свой id командой `/id` (доступна всем), затем владелец
  добавляет этот id в `.env` и перезапускает бота.
- 2FA-код принимается только если это цифры (3–8 знаков) — случайные сообщения
  других админов кодом не воспринимаются.

### Несколько кабинетов одновременно (мультиаккаунт)
- В `.env` добавьте остальные кабинеты: №1 — `SITE_LOGIN`/`SITE_PASSWORD`,
  №N — `SITE_LOGIN_N`/`SITE_PASSWORD_N` (подряд, начиная с 2),
  имя для уведомлений — `SITE_NAME`/`SITE_NAME_N`.
  Файлы сессий: `./data/auth.json`, `./data/auth_2.json`, …
- На каждый кабинет запускается своя задача-воркер: свои cookies, свой опрос
  очереди, свои заявки; в уведомлениях видно имя кабинета («[Кабинет 2] …»).
- Управление из Telegram:
  - `/run` — бот спросит кабинеты: ответьте `1 3`, `1,3`, `1;3` или `all`;
  - `/run 1 3`, `/run all`, `/runall` — то же прямо в команде;
  - `/watchall` / `/stopall` — наблюдение/остановка всех кабинетов сразу;
  - `/status` — «работает сейчас: N из M» и состояние каждого кабинета.
  - `/reset_session` (так же `1 3` или `all`) — очистить кэш очереди кабинета
    и пересчитать по площадке, когда счётчик «в работе» разошёлся с реальностью.
- Авторизация и 2FA идут по одной за раз (иначе непонятно, чей код вводится);
  горячие циклы полностью параллельны. Если кода ждут несколько кабинетов,
  присылайте номер и код: `2 123456`.
- Мультиаккаунт работает только на `WORKER_BACKEND=http` (по умолчанию).
  `WORKER_BACKEND=browser` при 2+ кабинетах запустит лишь кабинет №1 и напишет об этом в лог.
- Проверить, что кабинеты прочитались (секреты не печатаются, логин маскируется):
  ```bash
  python tools/check_accounts.py
  ```
  Скрипт покажет список кабинетов, пути файлов сессий, число админов и
  предупредит, если `WORKER_BACKEND=browser` не сможет запустить больше одного
  кабинета, а также подсветит переменные, «залипшие» в окружении терминала
  (`load_dotenv` их не перезаписывает — бот возьмёт значения из окружения,
  а не из `.env`; помогают чистый терминал или `unset SITE_LOGIN_2 …`).

## 6. Настройка селекторов
- Если вход не сработал или сайт показал неожиданную разметку, бот **прислал
  HTML+скриншот прямо в Telegram** (и сохранил в `./data/debug_*.png|html`) —
  по ним видно, что было на странице в момент сбоя.
- Селекторы страницы выплат (`SEL_ACTIVE_QUEUE_CARD`, `SEL_AVAILABLE_CARD`,
  `SEL_TAKE_BUTTON`, `ATTR_ORDER_ID`) сейчас заглушки. Пока они не
  заполнены, цикл ничего не возьмёт. Откройте страницу выплат в браузере,
  который запустил бот, нажмите F12 → Inspect на карточке заявки и кнопке
  «взять», и пришлите мне HTML этих элементов — я подставлю селекторы.

### Живой захват запроса взятия: `take_capture`

Пока API взятия у площадки неизвестен (SPA шлёт JSON через fetch), HTTP-цикл
не может взять заявку. В этом режиме работает отдельный инструмент — он держит
браузер **видимым** (в отличие от разовой авторизации, которая окно закрывает),
сам обновляет страницу и жмёт кнопку взятия, а заодно записывает реальный
запрос и ответ сервера:

```bash
# 1. сначала остановите бота в Telegram (/stop), чтобы не конкурировать
# 2. видимое окно: автообновление 3с, взять 1 заявку и снять запрос/ответ
python -m app.take_capture

# непрерывно брать кликом (страховочный режим, пока нет HTTP-API)
python -m app.take_capture --max-takes 0

# только смотреть/обновлять, ничего не нажимая
python -m app.take_capture --no-click
```

Что делает:
- открывает Chromium с уже сохранённой сессией (`./data/auth.json`); если
  сессия протухла — пишет об этом и ждёт, пока вы войдёте **вручную в том же
  окне** (`--login-wait`, по умолчанию 300 c), затем сохраняет cookies;
- раз в `--refresh` секунд перезагружает страницу очереди;
- ищет кнопку по тексту («Взять», «Забрать», `PAYOUT_TAKE_BUTTON_MARKERS`,
  `--button-text`) и кликает первую видимую и включённую;
- перехватывает сетевые запросы/ответы (URL, метод, заголовки, тело, статус)
  и складывает их в `./data/take_capture/take_<id>_<ts>.json` (+HTML и PNG);
- печатает готовые строки `.env` (`TAKE_API_URL_TEMPLATE`, `TAKE_PAYLOAD_FORMAT`,
  `TAKE_ID_FIELD`, `TAKE_REQUIRES_CSRF`) и `curl` для проверки.

Дальше эти значения переносятся в `.env`, и бот возвращается на
`WORKER_BACKEND=http` — уже без окна.

## 7. Горячий цикл на HTTP (по умолчанию) и замеры времени
Опрос очереди и взятие заявок работают на `httpx` — без браузера. Браузер
поднимается только для разовой авторизации, если сессия в `./data/auth.json`
перестала действовать. Переключение обратно на браузерный воркер — `WORKER_BACKEND=browser` в `.env`.

### Профиль 911pay (headless: заявки берутся без браузера)

Очередь площадки — Laravel + Inertia: строки лежат в JSON `props.payouts.data`,
id заявки — `uuid`, статус — код (`unassigned`, `pending`, `wait_admin`,
`returned_to_trader`, `success`, `canceled`, `expired`), а взятие — `POST
/trader/payouts/{uuid}/claim` **без тела** с csrf в заголовке `X-XSRF-TOKEN`
(значение cookie `XSRF-TOKEN`, URL-decode). Рабочий набор в `.env`:

```dotenv
WORKER_BACKEND=http
HEADLESS=true              # окно нужно только для разовой авторизации
PREDICTIVE_TAKE=false      # превентивное взятие выключено

TAKE_API_URL_TEMPLATE=https://911pay.net/trader/payouts/{id}/claim
TAKE_PAYLOAD_FORMAT=none   # POST без тела: id уже в URL
TAKE_REQUIRES_CSRF=false
TAKE_CSRF_HEADER=X-XSRF-TOKEN
TAKE_CSRF_COOKIE=XSRF-TOKEN
TAKE_GONE_MARKERS=срок выплаты истёк
TAKE_RETRY_COUNT=0         # не дублировать POST (успешный ответ ещё не изучен)

QUEUE_JSON_ID_FIELD=uuid
QUEUE_JSON_STATUS_FIELD=status
CONFIRM_REQUIRES_IN_WORK=true
DEMANDS_URL=https://911pay.net/trader/payouts/payout-list?page=1&per_page=50&tab=in-work
```

`parse_rows()` сам распознаёт Inertia JSON/`data-page` и переводит код статуса в
текст, поэтому `STATUS_*_MARKERS` продолжают работать. `tab=in-work` для
`DEMANDS_URL` — это ровно занятые слоты (маленькая страница), `tab=common`
отдаёт все 70+ заявок (сотни КБ). Подтверждение при `CONFIRM_REQUIRES_IN_WORK=true`
идёт только по статусу «в работе»: отменённая/истёкшая заявка не считается взятой.

⚠️ **Проверьте окружение терминала.** `load_dotenv()` НЕ перезаписывает уже
экспортированные переменные, поэтому старые `TARGET_QUEUE_SIZE`/`DEMANDS_URL`/
`HEADLESS` из прошлых запусков могут «перебить» `.env` (симптом: «в `.env` 8,
а бот пишет цель 10»). Теперь бот при старте сам пишет WARNING со списком таких
переменных, а `python -m app.main --check` показывает итоговые `цель=N заявок,
headless=…`. Помогает новый терминал или `unset TARGET_QUEUE_SIZE DEMANDS_URL HEADLESS`.

Важные настройки скорости (в `.env`):
- `TAKE_POLL_MIN_MS`/`TAKE_POLL_MAX_MS` — пауза между опросами очереди, когда заявок
  нет. Это главный рычаг задержки обнаружения: цикл опроса ≈ RTT запроса + пауза.
- `TAKE_PARALLEL_POLLERS` — сколько независимых воронок опрашивают очередь
  одновременно (по умолчанию 1). Больше — быстрее обнаружение, но выше нагрузка.

Про размер очереди:
- `TARGET_QUEUE_SIZE` — сколько заявок держать «в работе». Считается не по памяти,
  а по странице `DEMANDS_URL`: слот занимают и взятые нами заявки, и выданные
  площадкой автоматически (автовыдача), и оставшиеся с прошлого запуска процесса.
- `DEMANDS_SYNC_S` — как часто (сек) бот сверяется с этой страницей (по умолчанию
  10). Меньше — точнее счёт после автовыдачи/завершения заявок, но больше запросов.
  Перед стартом сверка делается всегда: бот напишет
  `📊 Сверка с площадкой: в работе уже N/M заявок … Возьму ещё K.`

Замеры времени каждого взятия пишутся в `./data/metrics.jsonl` (JSONL) и в лог
строкой `METRIC …`. Ключевое поле — `saw_to_sent_ms`: сколько прошло между
«увидели заявку в ответе GET» и «отправили POST». Рядом — `poll_rtt_ms`/`submit_rtt_ms`
(сеть), `since_prev_get_ms` (частота опроса) и `py_overhead_ms` (Python). Отдельная
запись `take_result` показывает, взяли заявку (`confirmed=true`) или упустили.
Посмотреть последние замеры:

```bash
tail -n 20 data/metrics.jsonl
```

Сводный отчёт по всем замерам (перцентили, разбивка по кабинетам, доля взятых
заявок → ответ на вопрос «нужен ли Go»):

```bash
python tools/metrics_report.py
```

## 8. Тесты (офлайн, без сети)
Запускаются из корня проекта на реальных HTML-дампах из `./data`:

```bash
python -m unittest discover -s tests -t . -v
```

Важно: тесты нужно запускать **интерпретатором проекта** (Python 3.10+, то есть
`.venv/bin/python` или `python` из активированного venv). На системном Python 3.8
`WorkerState` создаёт `asyncio.Queue` вне цикла событий, и два теста диалогов
падают с `RuntimeError: There is no current event loop`.

## Частые проблемы
- `Missing required env var` — не заполнен `.env` или вы запускаете не из
  корня проекта.
- Бот не отвечает — не нажали Start у бота, неверный токен, либо запущен
  второй экземпляр с тем же токеном (Telegram отдаёт обновления только одному).
- Бот отвечает, но игнорирует — `TELEGRAM_ALLOWED_CHAT_ID` не совпадает с вашим Id.
